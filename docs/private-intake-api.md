# Private uploaded ballot preview API

This opt-in API extracts and retains a **private, unverified** PDF, UTF-8 text file or pasted text. It does not add uploaded text to the official corpus, answer civic questions from it, run Strands/Decisions on it, translate it, or authorize speech. Existing retained-evidence answers keep their source/review gates. Claude owns presentation. The existing local `/website` form now connects upload/paste, selection and the qualified formula through a theme-neutral interaction module; this is not an uploaded AI-answer evaluator.

Start an untunneled loopback instance with `--intake`; default is off. This switch rejects non-loopback binds and extra allowed hosts. Native PDF processing remains local Poppler with the imported intake worker's bounds, **not a kernel sandbox**. Do not expose this endpoint through the private Site or a tunnel without separately reviewed parser isolation/admission.

## Private session and resource limits

All actions are same-origin POSTs with `X-Oracle-Session` set to the existing ephemeral UUID. No URLs, source headers, filenames, official status, arbitrary ranges, replacement quotes, model instructions or external storage are accepted. Responses are no-store; request logs remain off. Intake data is not projected into `/api/operations` or exported.

State lives inside the existing `VisitorSessions` entry, under its lock, cancellation event, capacity (32 sessions) and lazy expiry (600 seconds idle). At most four retained documents and 20 MiB **raw bytes per session**, plus one pending preview within those caps. One intake/body-reading/parser/calculation operation across the server; contention returns 429 rather than queuing. Preview discard releases its references; Erase drops all document/preview/selection/report references and sets the shared cancellation signal. Expiry is pruned on the next visitor operation; no promise of immediate process-memory zeroization. There is no provider deletion claim.

PDF: 5 MiB, 30 pages, 8-second total extraction deadline, imported CPU/output/RSS guards. TXT/paste: 256 KiB encoded / 80,000 Unicode code points. Selection: 20,000 code points, complete registered block only. JSON paste framing allows 1 MiB for escaped JSON; actual decoded text bounds still apply. Other JSON bodies allow 8 KiB; binary TXT 256 KiB. Read/delivery timeout is five seconds on intake requests, no automatic retry. Strict UTF-8 JSON, unique keys, finite values, single Content-Length/Content-Type and no chunked body. Core parser failures hold with fixed reasons, not raw exception details.

## Existing owner ticket

The frontend passes its **complete current ticket**, including `request_id`, `epoch` and the existing `generation` or `sequence`, with all existing language/voice identity fields when present. No replacement visitor controller or new epoch alias is minted. Ticket values obey the frozen intake's bounded JSON rules. IDs/counters are correlation and stale-result fences, not evidence/release authority; same-origin session ownership is checked separately.

The server owns `document_revision`, document/preview/selection handles and registered Unicode ranges. The client starts with state revision zero. Preparing does not invalidate or replace existing accepted reading. Before commit/selection, the host synchronously stops/invalidates its existing local request/audio owner, increments that owner's existing sequence/generation and uses a new request ID; failure to invalidate must hold the host action. The server independently rotates its session cancellation event under the same lock, invalidates the old event and drops contest context/speech receipt. It does **not** claim acknowledgement from another browser tab or from a provider.

A fresh commit/selection ticket must have exactly the same complete field set and all fields unchanged except a strictly increased existing sequence/generation and a different request ID. Locale/voice/session changes require discarding/repreparing under their current owner instead of transplanting an old preview. Erase remains the existing `/api/erase` or equivalent local command. Backend Stop/Resume acknowledgement and continuous voice remain separate incomplete seams.

## Endpoints

`POST /api/intake/state` — `{}`. Returns revision, private document metadata/active handle and current selection ID; no raw contents. Requires a current session. Public `/api/health` advertises enabled/schema/source-admission/readability status, never document or visitor state.

`POST /api/intake/prepare` — JSON `{"owner_ticket":{...},"expected_revision":0,"text":"complete supplied text"}`. Returns private extracted document preview, a one-use `prepared_id` and `requires_fresh_ticket_commit:true`. All extracted Unicode, original/extraction hashes, page/block ranges and warnings remain available privately. No silent trimming or source promotion. A pending preview must be committed/discarded before another is prepared.

`POST /api/intake/upload` — raw binary body, `Content-Type:application/pdf` or `text/plain`, and **ASCII JSON** `X-Oracle-Intake:{"owner_ticket":{...},"expected_revision":0}`. JSON escape non-ASCII metadata; the decoded complete ticket is preserved. Only the content type determines PDF/TXT parsing; no filename is used. One leading TXT UTF-8 BOM is handled by the existing explicit decode rule; raw-byte and exact extracted-text hashes remain distinct. PDF empty/image-only/blank pages hold selection with OCR/copy-and-paste fallback; no OCR provider exists.

`POST /api/intake/commit` — JSON `{"prepared_id":"...","expected_revision":0,"owner_ticket":{...fresh...}}`. After extraction succeeds and owner currentness is rechecked, atomically invalidate old server work and retain the private document with revision +1. Returns `document_id`, complete fresh ticket/preview, `source_acceptance:not_run`, `translation:blocked`, `speech:false`. Old prepared handles/revisions cannot replay. Existing document history remains bounded; only the active document can be selected. No restore/reinterpret-old-document route exists yet.

`POST /api/intake/discard` — `{"prepared_id":"..."}`. Drops a matching pending preview only. Idempotent, cannot delete another session's document.

`POST /api/intake/select` — JSON with exactly `document_id`, `expected_revision`, `block_id`, `confirmed_complete:true`, `owner_ticket:{...fresh...}` and `method_language_assumption:null` or `"en"`. Core resolves the registered block, rechecks raw/extracted hashes and Unicode half-open ranges, computes over **the complete exact quote** and checks owner currentness again before atomic install. It returns a private selection and bound diagnostic only, outside AcceptedStore/source/translation/speech. `q1`/`q2` are detector ordinals, not printed ballot IDs. `whole` is always labelled **whole-document**, even when headings were not detected; never imply a per-question calculation on a whole ballot. Incomplete confirmation or non-selectable extraction produces a held contract error. Selection also invalidates pending previews/prior selection reports and server answer receipts.

## Explicit English formula diagnostic

`method_language_assumption:null` holds with `unsupported/explicit_method_choice_required` and null report. Choosing `en` permits a separate **English formula estimate** under `explicit_english_formula_assumption`. Keep the qualifier beside the first number: **“You selected English; source language not verified. This formula does not test comprehension, accuracy or legal meaning.”** Source locale stays `unknown`, provenance stays `unverified_user_content`.

The current scorer uses caller-declared English with ASCII letters, not a language detector: ASCII Spanish can calculate conditionally and accented English can be unsupported. No accents/characters are stripped, transliterated or translated to gain support. Known non-English source assessment cannot be overridden by the method choice. No source-language assessment is provided by this API; UI locale is never one.

The unchanged `analyze_readability` is called directly, never its corpus-bound `verify_diagnostic` or a spoofed Strands tool execution. The diagnostic binds exact selection quote hash, document revision, raw/extracted hashes, registered block/range, fresh owner ticket and method/dependency hash. Counts and four-decimal FRE/FKGL estimates are separate from `clarity:{status:not_run}`. No new grade bands/composite/comprehension claim. States: `calculated_under_assumption`, `unsupported`, `empty`, `unavailable`; cancellation/stale/Erase returns a held HTTP result before report installation. Null scores are never zero. Audited scorer cleanup has a separately hashed scored representation and never rewrites the original selection.

Frozen language-v1 accepts only independently core-accepted English evidence. Unknown/non-English intake is blocked before that adapter. Formula choice, completeness confirmation or hash matches cannot satisfy this gate. The private selection is not a quality/translation/speech receipt.

## Validation and activation boundary

Tests cover actual loopback HTTP + native retained PDF extraction, strict framing/admission, Unicode/full-condition binding, method assumptions/unsupported values, replay/cross-session identity, caps, expiry, Erase during parser/formula work, source replacement during an existing evidence request, and unchanged content-free operations/corpus counts. No external inference, microphone, speaker or browser capture in these tests.

The shared signal identity is also checked before answer/event/audio delivery so a source replacement cannot retain/release prior server-generation output. This cannot retract bytes already sent; clients must still fence late display and close local playback synchronously.

End-to-end proof used an untunneled source-only loopback intake instance, both typed routes and the landing. Private intake stays separate from a forwarded listener. Remaining: presentation refinement, source-language/provenance admission, actual uploaded-text Strands/Decisions evaluator, translation release, continuous voice/Stop acknowledgement and human audio acceptance.

## Reusable landing ownership and Claude integration

`web/intake.js` exposes `OpenOracleIntake.createOwner()` and `mount(form, owner)`. `web/website.js` creates **one** `OpenOracleWebsiteOwner` for the landing because this surface previously had no request owner. Its `next()` synchronously aborts prior work and returns the complete `{epoch,sequence,request_id}` ticket, visitor UUID, AbortSignal and a currentness predicate. `invalidate()` discards local currentness; `erase()` rotates the visitor UUID and sends the old session to the existing Erase endpoint. Future language/voice adapters on this surface must consume that owner, not create another one. Kiosk `app.js` keeps its existing separate owner, unchanged.

Source edits and Cancel synchronously hide prior preview/report, invalidate requests and rotate/Erase the old session. Cancel preserves the supplied input for a **deliberate new** Read ballot, but clears the server preview/document. This is explicitly cancellation-and-clear, not a backend Stop/Resume or provider acknowledgement. It also solves cancellation before a prepared ID arrives. Erase additionally clears textarea/file chooser/quote/report and focuses input. Page hide drops local content and requests old-session Erase without claiming guaranteed completion.

Minimal functional composition contract (no new palette/layout/CSS): load `/intake.js` before `/website.js`; preserve `#ballot-form`, `#ballot-file`, `#ballot-wording`, `#read-ballot`, `#cancel-intake`, `#clear-wording`, `#wording-count`, `#wording-limit`, `#evaluator-status`. Native selection/result controls are mounted into that form with IDs `#intake-block`, `#intake-complete`, `#intake-english`, `#intake-calculate`, `#intake-result`, `#intake-assumption`, `#intake-scores`, `#intake-original`, `#intake-selected-quote`. Dynamic original text is assigned with `textContent`, never model/visitor HTML. Do not move this calculation into AcceptedStore or label the whole-document option per-question. Without `health.intake.enabled`, Read ballot stays disabled and retained-source demo links remain available. No automatic server startup, provider call, file transfer or permission request.

Run `node scripts/intake_browser_acceptance.cjs http://127.0.0.1:<owned-port> <ignored-evidence-dir>` against a provider-off `--operations --intake` instance. It uses the existing Playwright/Chrome runtime, real private HTTP requests and retained public PDFs; screenshot fixtures are ignored, result reports omit private text and IDs. Do not run parallel intake suites on the same one-parser instance unless testing the explicit429 contention outcome.
