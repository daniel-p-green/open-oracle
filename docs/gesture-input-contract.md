# Gesture input contract: nonvisual checkpoint

Only the capture-free producer and bounded scalar stdin/poll transport are integrated. `--sensor-hand-gestures` is default off and requires `--sensor-stdin`. It installs no camera, recognizer, model, permissions, network service or browser hook. The active app has no gesture assets or controller. Frozen browser policy/controls remain in task-11 for contract review.

`HandObservationProducer` consumes an existing recognizer result and actual acquisition timestamp supplied by the supervised hardware owner. It emits `open-oracle-input/v1` envelopes with session, monotonic timestamp, sequence and synthetic flag. A hand event includes only count (0/1/2), independently supplied scene stability, normalized palm x/y/width, category score, finite allowlisted pose label and left/right side. No pixels, landmarks, identity, transcript or media are retained. Synthetic defaults true and production transport rejects it; real metadata requires explicit camera authorization and foreground readiness. Scene stability defaults false; hands cannot prove independent occupancy or departure.

InputEvents rejects malformed, stale/future, replayed and synthetic envelopes, strips extraneous payload, caps the queue and expires the frame lease. Presenter navigation carries only previous/next. Camera loss is unknown, never manufactured departure. A camera detector must observe at least two hands, preserve aspect ratio and independently verify single-participant continuity, real frame freshness, latency and mirroring before physical enablement.

The future browser policy uses answer-bound navigation/ephemeral helpfulness, with stale pointer/held-key guards. It is not installed. The staged wave-starts-voice action conflicts with the draft wave-opens-controls flow and remains held pending resolution. No active gesture UI remains. The future actions checkbox does not stop the separate camera-owner process. Physical accuracy, fairness, lighting/skin tone robustness, frozen-pixel behavior, Pi latency/temperature and presenter mapping are unverified. No model weights or redistributed model license are supplied.

Validation: full offline Python suite ran 221 tests with four optional integration skips. Hand producer plus transport suites ran 18 tests including owned loopback HTTP. Existing / and /copilot actual offline Chrome checks pass source/attribution, both requested COMBAT facts, scoped/mixed candidate followups, visible gaps, reset/fresh response and late-display rejection. No physical capture, provider calls, external requests or live gesture claims. Frozen isolated browser policy has 26 authored groups; that result does not certify integrated browser hooks or physical recognition.
