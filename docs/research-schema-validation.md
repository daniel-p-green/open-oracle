# Research schema validation repair

Installed Strands 1.59.0 converts nonrequired array fields to nullable tool inputs. The prior `CitedAnswer` schema used default empty lists, so its generated native tool schema accepted `claims: null` and `gaps: null` while Pydantic rejected them with `list_type`. A local test reproduces that discrepancy using the installed native `StructuredOutputTool`, JSON Schema validation and Pydantic. The repaired model explicitly requires the two arrays in its emitted schema; the prompt requires `[]` for empty arrays. Internal empty-list defaults remain available.

This is an observed contract mismatch, not a diagnosis of the earlier live failures. That receipt retained two failed `CitedAnswer` tool events but no argument values or failing fields. Their cause remains unknown. The repair does not relax source binding, the 0.95 review threshold, cancellation, token limits or display guards. No further provider test has run.

A request-local collector records only schema name `cited_answer_v1`, its definition SHA256, a fixed validation category and a normalized allowlisted field path. Array indices become `*`; arbitrary extra-field names become `unrecognized_field`. It excludes validation messages, input values, contexts, URLs, arguments, model text and visitor content. Projection emits at most eight events per validation; the independent receipt validates each four-key shape and stores at most 32 events (or its lower configured limit), with a dropped-event count. Finished receipts ignore late additions.

An app-owned execution-failure boundary carries a completed safe receipt to the unavailable response. It releases no draft, evidence claims or quality approval. Failures without this completed receipt still have unknown SDK usage rather than fabricated zero counts. ContextVar collectors are reset in `finally` and isolated between concurrent requests.

Validation uses actual installed Strands SDK with authored synthetic model events, not live inference: malformed-then-valid arrays produce precise bounded categories; repeated malformed outputs remain unavailable with a completed receipt. Separate privacy canaries cover unknown fields and nested values; receipt checks cover independent rejection, storage bounds, finalized snapshots and defensive copies; concurrent collectors do not cross threads. Run `tests/test_schema_contract.py` and the full Python suite. The earlier live trial remains documented separately in `docs/semantic-targeted-held-20261011.md`.
