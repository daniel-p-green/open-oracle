# Open Oracle: operational measurements and evaluation handoff

Use **Promptfoo for regression/configuration comparisons, Decisions for explicit application predicate review, and content-free Strands receipts for runtime measurement**. AWS observability is a complementary export destination. This patch provides measured local collection and a readout; managed ingestion remains unverified.

## Integration boundaries

New files: `oracle_observability/{__init__,monitor,schema,traces,readout,evaluation}.py`, `evals/observability_provider.py`, `tests/test_observability.py`, this document. Core owns applying `server-eval-integration.patch` to `open_oracle/server.py` and `promptfooconfig.yaml`, plus the separately frozen `schema-receipt.patch` to `strands_quality/receipts.py`.

The server hunk creates one monitor after engine/triage construction, wraps the engine once, and adds `--operations`, `/api/operations` and `/operations`. It rejects non-loopback hosts and configured tunnel aliases when operations readout is enabled. No production listener was changed by this worker. Core must verify the integrated deployment hashes after copying the new package; the isolated HTTP proof used virtual staged server hunks over the current canonical app.

Schema seam: `EvidenceReceipt.schema_validation(**event)` independently checks the exact four-key event shape, fixed schema name, SHA256, category and normalized field path using core's `strands_quality/schema_validation.py` constants. Retain at most `min(max_events,32)` events, count overflow, ignore post-finalization calls. The monitor and trace layer independently revalidate the same contract. No Pydantic `msg`, `input`, `ctx`, URL, arbitrary key, numeric index or tool argument survives. Generic tool errors stay `tool_result_error` where no sanitized validation event exists.

The monitor never retains raw questions, answers, audio/video, identity/network identifiers, session IDs, credentials, model/tool payloads or provider request IDs. Request/run UUIDs and released source versions exist only in the transient projection and explicitly enabled trace sink; aggregate snapshots retain neither. These UUIDs are pseudonymous, not proof of anonymity. Process aggregates survive visitor erase because they contain no visitor linkage; app erase/cancellation remains core's responsibility. No persistent visitor-data collection is introduced.

Helpfulness is an optional aggregate-only Boolean method. No UI control or HTTP feedback endpoint was added. Counts do not measure unique visitors, comprehension or voting preferences.

## Evaluation and reporting rules

The adapter returns the application result, `latencyMs`, component usage and correlation/version metadata in the [official Python provider format](https://www.promptfoo.dev/docs/providers/python/). Held answers are outputs to assert against; execution exceptions become fixed-category errors. Missing paid usage is unknown. Component counts are observed attempts, not billing invoices. Explicit caller estimates may populate `cost`; no default rate is fabricated.

**Installed Promptfoo 0.123.1 reporting quirk:** the actual 53-case run reports top-level `stats.tokenUsage.numRequests=53` even though all returned provider responses declare zero and all three component counters are zero. Treat that CLI total as wrapper invocations for this run. Use `response.metadata.component_usage`, `usage_complete`, and `provider_request_count_basis` to measure provider attempts. An incomplete live count is an observed lower bound; unknown component names are explicit. Do not equate the CLI request total with model calls.

For an explicitly authorized live comparison, inject `EvaluationAdapter(engine, versions, public_cases=..., before_paid_case=..., measured_usage=...)` with a frozen public-case manifest, actual research engine and budget reservation callback. `measured_usage` is owner-owned **per-case** embedding counters/estimated cost, not cumulative process usage. The default provider refuses an execution-mode switch. Existing provider deadlines, cancellation and no-retry limits remain authoritative. Never send visitor transcripts into Promptfoo fixtures.

Reuse the application's named Decisions predicates; don't add a generic `llm-rubric` judge. The [official Decisions provider](https://www.promptfoo.dev/docs/providers/openai-decisions/) also supports explicit named predicate evaluation if a separate, reserved reviewer experiment is needed. Do not run both merely to duplicate review. Keep source binding, scope/date, qualifiers, no-vote-advice and erase isolation deterministic. Thresholds require human-labelled calibration; latency p95 is not inferred from this small sample.

## Trace privacy and AWS preflight

[Strands tracing](https://strandsagents.com/docs/user-guide/sdk/observability-evaluation/traces/) can include messages, prompts and tool arguments/results. Installed 1.59.0 defaults preserve sensitive attributes unless its redaction configuration is enabled. This patch does **not** activate SDK global exporters or depend on a broad environment flag for privacy: it uses its own resource/provider/scope and re-projects attributes. Root/child spans share trace ID, with trusted request/run/config correlation. Stage/tool/model durations are measured numeric attributes on completed-operation spans; their emitted wall-clock intervals are not fabricated original execution timestamps. No span events or exception descriptions are emitted.

Default monitor has no emitter. Local tests used an in-memory exporter only. `approved_otlp_emitter` is an explicit generic HTTP-OTLP seam, with approval argument, explicit destination, bounded queue/payload/transport timeout and transport-config preflight. It rejects ambient OTLP transport configuration; no global environment is rewritten. It is not a SigV4/ADOT AgentCore implementation. OTel transport may retry within its timeout; model calls are never retried by this adapter. Batch export failures and successes are counted, but a success means exporter acceptance, not confirmed CloudWatch dashboard ingestion. Async export is bounded and best effort; queue drops are possible and are not inferred from successful spans.

Before enabling any network/cloud sink, core/AWS owner must verify the existing permitted account/profile/region, log retention, CloudWatch Transaction Search, ingestion IAM permissions, destination/service attributes and current charges. [AWS's AgentCore setup](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-configure.html) supports agents outside AgentCore Runtime using ADOT SDK, currently requiring ADOT >=0.18.0; no runtime migration is necessary. Its ingestion path is not the same as a generic OTLP collector. `AWS_GENAI_CONTENT_EXTRACTION_OPT_OUT=true` is not a safe redaction assumption. Audit actual serialized attributes/events/logs with canaries before export.

No AWS read, provisioning or export was attempted in this worker's implementation run. No new IAM role, credential, persistent authentication/security setting or uncertain billable resource is authorized by this patch. CloudTrail account/API audit history is separate from runtime traces and evaluation quality; no application CloudTrail integration is proved.
